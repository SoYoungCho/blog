안녕하세요! 데이터/AI 전략 PM 조소영입니다 :)
지난번에는 클로드 코드로 나만의 일기앱을 기획한 글을 썼는데요, 이번에는 바이브 코딩으로 나만의 블로그를 만든 후기를 공유하려 합니다.

이 글에서 다루는 것

  • 코드를 직접 짜지 않고, 클로드 코드(Claude Code)와 대화만으로 블로그를 만든 바이브 코딩 과정
  • 노션에 글을 쓰면 블로그에 자동으로 올라가는 노션 블로그 자동화 플로우
  • 구글 로그인 댓글, 답글 메일 알림, 방문 통계 대시보드, SEO/GEO까지 넣은 기능들
  • 비용: 0원 (무료!) → 무료로 만들 수 있었던 이유

1. 블로그를 시작한 이유

사실 일하면서 너무 재밌는 프로젝트도 많이 했고, 평생 못 잊을 경험도 많이 쌓았는데 외부에 공유한 적은 한 번도 없었어요.

(챗GPT가 나오기도 전인 2021년 프롬프트 엔지니어링으로 LLM 챗봇 서비스를 만든 후기 (이때는 관련 한글 서적은 물론, 한글 문서도 거의 없었어요), 영 라이언즈 대회에서 한국 대표로 선발된 후기 등.. 다 나중에 글로 풀게요!)

학부 때부터 이것저것 다양한 삽질하는 걸 좋아해서, 혼자 낑낑대다가 얻은 인사이트들을 주위에 공유도 하고, 대학 강연으로 발표도 하곤 했는데요. 좀 더 많은 사람들에게 제가 한 고민과 생각, 경험과 느낀 점을 공유하고 싶어서 블로그를 써야지 했습니다. 또 글을 쓰면서 다시 한번 제 경험을 정리해 보고 싶은 마음은 당연하구요!

2. 기존 블로그 플랫폼은 왜 안 썼을까

이전이라면 만만한 네이버 블로그를 썼을 텐데, 이제는 더 많은 채널에 노출되고 싶기도 하고, 네이버 블로그는 일상/로컬 관련 소재에 더 적합한 채널인 것 같아서 다른 매체를 고민해 봤어요. 다른 플랫폼들도 하나씩 써 보니 다 조금씩 아쉬웠습니다.

플랫폼좋은 점아쉬웠던 점
네이버 블로그쓰기 쉽고, 네이버 검색 유입이 많음구글 검색 노출이 약한 편이고, 맛집, 여행, 후기 같은 생활 정보 위주
티스토리구글 검색 유입, 디자인 수정 가능개발 블로그 느낌, UI가 마음에 쏙 들진 않음
velog마크다운으로 쓰기 편함개발 주제 위주, 폰트가 안 예쁨
브런치감성적인 글쓰기, 매거진 연재콘텐츠 삽입에 제약, 테크니컬한 경험보다 에세이형 브랜딩
미디엄세련된 글쓰기, 글로벌 독자국내 독자가 적고, 폰트가 안 예쁨..

3. 내가 원한 블로그의 조건

운영의 자유도

제가 가장 중요하게 생각한 건 운영의 자유도!예요. 디자인이나 유저 플로우, 폰트, 기능들을 제 마음에 들게 만들고 싶었고, 각 플랫폼의 강점을 하나로 합친 나만의 사이트가 있었으면 했어요. 그래야 더 애정 어린 마음으로 가꿀 수 있을 것 같았습니다.

노션에서 바로 쓰는 글쓰기

그리고 무엇보다 글쓰기 접근성이 높았으면 했어요. 저는 직관적이면서 따뜻한 느낌의 노션을 좋아해서, 노션 페이지에 글을 쓰면 자동으로 블로그에 예쁘게 발행되는 자동화 플로우를 원했습니다.

그래서 제가 선택한 방법은 클로드 코드로 직접 깃허브 블로그(GitHub Pages)를 만들고, 노션에 글을 쓰면 자동으로 발행되게 하는 것, 이른바 노션 블로그 자동화였어요.

4. 만든 과정

생각보다 어렵지 않았어요. 클로드한테 피드백을 주어 가며 요청하니 셋업이 수월했습니다.

어떻게 만들까

내 경험을 기록하고 공유할 블로그를 만들고 싶어. AI 활용, 업무 기록, 일에 대한 생각을 주로 쓸 건데, 어떤 플랫폼이 좋을까?

여러 선택지를 비교해 보니, Astro로 블로그를 만들어 GitHub Pages에 무료로 올리는 방식이 제 조건에 가장 잘 맞았어요. 일단 빠르게 띄워 보고, 직접 써 보면서 하나씩 고쳐 나가기로 했습니다.

*Astro: 마크다운으로 쓴 글을 웹페이지로 바꿔 주는 도구. GitHub Pages는 서버 없이 완성된 페이지 파일만 올려 두는 곳이라, 글을 미리 페이지로 만들어 줄 도구가 필요한데, Astro가 그 역할을 해줍니다. 이렇게 만든 페이지는 가볍고 빨라서 검색엔진에도 잘 잡힌다고 해요.

Design : 당근, 토스에서 Mobbin까지

디자인은 가독성과 심미성을 최우선으로 두고, 앞으로 올릴 글들의 특성상 테크 블로그의 포맷을 참고해야겠다 싶어서, 평소에 좋아하는 당근 블로그와 토스 블로그를 레이아웃 레퍼런스로 줬어요. AI 활용 경험이나 업무 기록처럼 스크린샷, 표, 단계별 설명이 많이 들어가는 긴 글을 쓸 예정이라, 이런 글을 편하게 읽히게 만드는 데 익숙한 테크 블로그가 잘 맞겠다고 생각했습니다.

그랬더니 레이아웃은 깔끔하게 잡혔는데, 파란 포인트 컬러에 흔한 카드 배치라 어딘가 AI가 만든 템플릿 같은 티가 났어요. 그래서 getdesign.md에서 블랙/화이트 중심의 깔끔한 컬러 팔레트를 가진 Mobbin 디자인을 찾아 레퍼런스로 한 번 더 줬습니다. Mobbin의 흰 바탕에 블랙~먹색으로 포인트를 준 톤앤매너, 알약 모양의 라운드 쉐입을 블로그에 그대로 가져왔어요.

*getdesign.md는 유명 서비스의 디자인 규칙(색, 글꼴, 버튼 모양 등)을 AI가 읽기 좋은 DESIGN.md 파일로 정리해 둔 사이트예요.

읽는 사람 입장에서 편하게 만드는 데도 신경 썼어요. 한글이 예쁘게 보이는 Pretendard 폰트를 쓰고, 글마다 읽는 데 몇 분 걸리는지 표시해서 부담 없이 읽기 시작할 수 있게 했습니다. 링크를 눌러 폰으로 보는 사람들도 많을 것 같아서, 모바일 화면도 하나하나 확인하며 다듬었어요.

글쓰기 : 노션에 쓰면 자동 발행

처음엔 블로그 사이트에서 바로 글을 고치고 싶었어요. 그런데 클로드왈: 지금 블로그는 완성된 페이지만 올려 두는 정적 사이트라, 사이트 안에는 글을 저장할 곳이 없다고 하더라구요. 대신 Pages CMS라는 웹 편집기가 있긴 한데, 노션과는 다른 별도 편집 화면이라 손에 익지 않을 것 같았고, 사진이 들어간 표는 깨져 보일 수 있다는 점이 마음에 걸렸어요.

그러다 이전에 어떤 분이 노션에 쓴 글이 자동으로 사이트에 발행되게 만든 사례를 봤던 게 기억났어요. 평소 잘 쓰는 익숙한 노션에서 게시물들을 관리하고, 편집하고, 발행까지 할 수 있다면, 쓰는 곳과 올리는 곳이 하나가 되어서 가장 편할 것 같다는 생각이 들었습니다. 그래서 노션 API로 노션과 블로그를 연동했고, 지금은 노션에서 글을 다 쓰고, ‘상태’ 속성을 작성중에서 ‘발행’으로 바꾸기만 하면 블로그에 올라가요.

발행 플로우

매시 정각에 GitHub Actions가 노션에서 ‘발행’ 글을 가져와 블로그 페이지로 만들고, 발행까지 알아서 해 줍니다.

노션의 마크다운 형태도 블로그에서 그대로 잘 읽히게 했어요. 제목, 목록, 인용, 표, 코드 같은 블록이 블로그 스타일에 맞게 옮겨지고, 사진 두 장을 나란히 둔 2단 배치도 블로그에서 나란히 보여요.

5. 이런 기능들로 고도화 했어요

누구나 쓸 수 있는 댓글과 답글 메일 알림

처음 만든 블로그 초안은 글만 덜렁 올라가 있어서, 기능을 하나씩 덧붙였어요. 가장 넣고 싶었던 기능은 댓글이었는데요, 인증을 거치지 않은 누구나 익명으로 글을 쓰는 건 부담스러워서 로그인한 사람만 댓글을 달 수 있게 했습니다.

깃허브 블로그는 서버가 없는 정적 사이트라 댓글 기능이 따로 없어서, 보통 utterances나 giscus 같은 GitHub 계정 기반 댓글을 붙인다고 들는데, 그럼 댓글을 달려면 GitHub 계정이 전부 있어야 하는 건가? 싶더라구요.

하지만 개발자가 아니면 깃허브 계정이 없는 경우가 많고 로그인도 번거로워서, 저는 더 대중적인 구글 계정으로 로그인을 연동했어요. (클로드가 시키는대로 따라했어요)

  • 구글로 로그인한 누구나 공개/비공개 댓글을 달 수 있어요.
  • 제가 답글을 달면 메일로 답글 알림이 가요. (그러니 게시물 관련 궁금한 점이 있으면 언제든 편하게 물어봐 주세요!)
  • 답글에 다시 답글을 다는 대댓글도 되고, 새로고침하지 않아도 새 댓글이 바로 보여서 대화하듯 주고받을 수 있어요.
  • 프라이버시 보호 차원에서 구글로 로그인해도 이름과 프로필 사진은 보이지 않고, ‘택배 뜯는 두부’ 같은 랜덤 닉네임으로 보이게 했어요. 닉네임은 직접 바꿀 수도 있습니다.

나만의 방문 통계 대시보드

그리고 블로그 대시보드를 만들어서 트래픽과 추이, 유입 채널 등을 볼 수 있게 했어요. 한 화면에서 이런 것들을 볼 수 있습니다.

  • 요약: 오늘/최근 30일/누적 조회수와 방문자, 날짜별 추이
  • 유입 채널: 링크드인, 검색, 직접 방문 등 어디서 들어왔는지와 채널별 추이
  • 유입 경로 상세: 어떤 사이트, 어떤 UTM 링크로 들어왔는지
  • 글별 성과: 글마다 조회수, 평균 스크롤, 완독률, 좋아요, 댓글, 공유
  • 리텐션과 기기: 처음 온 방문자와 다시 온 방문자, 휴대폰/컴퓨터 비율
  • UTM 링크 만들기: 링크드인에 공유할 때 쓸 추적 링크를 바로 만들어요

검색엔진과 AI 검색에 잘 보이게 : SEO & GEO

개인 사이트인만큼, 검색 최적화, SEO와 GEO까지 챙겼습니다. 저도 SEO / GEO는 생소한 개념이였는데, 이참에 조금이나마 알게 되었어요.

자세한 설명은 토글을 눌러 확인해보세요!

1) 사이트맵, RSS

  • 구글 서치 콘솔에 블로그를 등록하고, 사이트맵과 RSS를 자동으로 만들었어요
  • 사이트맵은 블로그에 어떤 글이 있는지 알려 주는 목록이라, 검색엔진이 새 글을 빠짐없이 찾아갈 수 있는 역할을 합니다.

2) 구조화 데이터

  • 글마다 정보를 검색엔진이 읽기 쉬운 형식(구조화 데이터)으로 넣었어요. (작성일, 수정일, 글쓴이, 읽는 시간 등)
  • 예를 들어 이 글에는 ‘글쓴이: 조소영, 작성일: 2026년 10월 30일’ 같은 꼬리표가 보이지 않게 붙어 있어요.
  • 덕분에 구글 검색 결과에 날짜나 글쓴이가 함께 보일 수 있고, AI 검색도 누가 언제 쓴 글인지 정확히 알 수 있습니다.

3) IndexNow

  • 새 글이나 고친 글이 생기면 IndexNow로 검색엔진에 ‘이 주소가 새로 생겼어요’ 하고 바로 알릴 수 있어요.
  • 원래는 검색엔진이 블로그를 다시 둘러보러 올 때까지 며칠이 걸릴 수도 있는데, 먼저 알려 주니 훨씬 빨리 반영된다고 합니다.
  • Bing, 네이버 등이 이 방식을 지원하고, 구글은 지원하지 않아서 서치 콘솔로 따로 챙겨야 한다고 해요.

4) GEO: llms.txt

  • ChatGPT나 Perplexity 같은 AI 검색이 내 글을 잘 읽어 가도록, llms.txt와 llms-full.txt도 따로 만들었어요.
  • llms.txt는 쉽게 말해 AI에게 건네는 블로그 안내문 같은 파일인데, 블로그가 어떤 곳이고 어떤 글이 있는지 짧게 정리해 두었고, llms-full.txt에는 전체 글 본문을 텍스트로 모아 두었습니다.
  • 두 파일 모두 글을 발행할 때마다 자동으로 새로 만들어져서, 새 글이 올라가면 목록에도 바로 추가돼요.

실제 llms.txt는 이런 식으로 생겼어요.

  • 같은 테마의 글을 묶는 매거진과, 누르면 관련 글이 모여 보이는 태그
  • 글 아래 내 프로필과 추천 글
  • 글 속 소리 플레이어 (필요 시 사운드를 직접 들어볼 수 있게 했어요)

6. 비용은… 0원!

꽤나 마음에 드는 블로그가 탄생했는데요, 돈은 하나도 들지 않았어요! (구독하는 클로드의 소중한 토큰들만 썼어요 ㅎㅎ)

이렇게 무료로 만들 수 있었던 이유는, 주요 기능에 쓴 이 친구들이 모두 무료로 제공되기 때문이에요.

도구하는 일무료인 이유
GitHub, GitHub Actions코드 보관, 매시 정각 자동 발행개인 계정은 무료이고, 자동 실행도 한 달 2,000분까지 무료
GitHub Pages블로그 사이트 공개공개 저장소의 사이트는 무료로 올려 줘요. 주소도 soyoungcho.github.io를 그대로 써서 도메인 비용이 없어요
Notion API노션 글 가져오기무료 요금제에서도 연동 키를 만들어 쓸 수 있어요
Supabase댓글, 좋아요, 방문 기록 저장, 구글 로그인 처리무료 요금제(데이터 500MB)로 충분해요. 일주일 동안 요청이 없으면 잠드는데, 발행할 때마다 깨워 둬요
Google Apps Script답글 알림 메일 발송내 Gmail로 하루 100명까지 무료
Google Search Console구글 검색에 블로그 등록, 검색 현황 확인무료
IndexNow새 글, 고친 글 주소를 빙, 네이버 등에 바로 알림무료

7. 직접 만들어 보니

모든 부분을 내 마음대로 바꿀 수 있다는 게 너무 좋아요. 글이 쌓일수록, 글의 성격에 따라, 또 읽어 주시는 분들에 따라 UI와 디자인을 계속 개선하려 합니다. 조금 더 개선하고 싶은 부분은 SEO, GEO 쪽인데, 중요한 건 꾸준히 기록하는 것이니까 차차 고민하며 사이트와 글의 구조도 다듬어 나가려고 해요.

바이브 코딩으로 블로그를 만들어 보고 싶다면

  1. 어떤 블로그를 만들고 싶은지 목적과 타겟을 먼저 생각해 보세요.
  2. 마음에 드는 블로그를 레퍼런스로 주면 디자인이 훨씬 빨리 잡혀요. getdesign.md 같은 사이트의 DESIGN.md 파일을 주면 더 정확해요.
  3. 처음부터 다 정하지 말고, 일단 배포해서 링크부터 받아 본 다음 하나씩 고쳐 나가면 돼요.
  4. 마지막으로… 이 블로그 글을 AI에게 던져서 “이런 식으로 만들고 싶다!” 해보세요 :>

코딩 할 줄 몰라도, 비전공자라 지식이 없어도 만들고 싶은 게 분명하면 AI와 함께 생각보다 많은 걸 만들 수 있는 걸 매일 느끼는 요즘이에요. 블로그를 바이브 코딩으로 직접 만들어 보거나, 노션으로 블로그 자동 발행하고 싶으셨던 분이라면 이번 주말에 가볍게 시작해 보세요.

궁금한 부분이나, 만들다 막히는 부분이 있으면 댓글로 물어봐 주세요. 답글을 달면 메일로 바로 알려 드릴게요 :) 재밌게 읽으셨다면 아래 좋아요 부탁드립니다!
